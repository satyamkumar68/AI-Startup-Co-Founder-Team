# Cofounder Improver

Turn "multi-agent debate improves quality" from a claim into **measured evidence**, and stop hallucinated numbers in outputs.

## Hard rules
- **Never invent metrics or sources.** All scores, costs, and URLs must come from actual runs/tool calls. Unknown → "not measured".
- Do not break existing exports (PDF/PPTX/Markdown/CSV) or the 57 existing tests. Run tests after every step.
- One commit per step; message format `feat|test|docs|ci: <what>`.
- Use a **different model family for judging** than for generating when possible; record model names/versions in results.
- Add a hard token/$ budget cap to any new batch script so it cannot run away.

## Step 0 — Orient
Read README, LangGraph graph definition, agent prompts, schema/validation code, exports, tests. Write `docs/CURRENT_STATE.md` (graph nodes, providers, test count, gaps). No code changes yet.

## Step 1 — Run modes (enables ablation)
Add config flag `MODE` = `single_agent | multi_no_debate | multi_debate`.
- `single_agent`: one strong prompt producing the same deliverables (same schema).
- `multi_no_debate`: agents run once, no critique/revise loop.
- `multi_debate`: current behavior.
Same model, same temperature, same input ideas across modes. Log tokens, $ cost, wall time, retries, schema-repair count, fallback count per run.

## Step 2 — Idea set
Create `eval/ideas.jsonl` with 30–50 startup ideas: mix of good, mediocre, and unrealistic/impossible; multiple sectors; some India-specific. Mark LLM-generated ones `needs_review: true`.

## Step 3 — Scoring
Create `eval/score.py`:
- Rubric (1–5 each): market realism, internal consistency (TAM→SAM→SOM math, PRD↔architecture), feasibility of architecture/cost, specificity, risk awareness.
- LLM judge from a different model family; pairwise comparison (win-rate) plus rubric means.
- `eval/human_scoring/` : generate a blinded CSV (shuffled, mode hidden) for the owner/peers to score ≥10 ideas. Provide `eval/merge_human.py` to join results. Do not fabricate human scores.

## Step 4 — Ablation report
`make ablate` → runs all 3 modes × all ideas (respect budget cap), writes `eval/results/ABLATION.md` with:
- Mean ± std of rubric scores per mode, win-rates, cost/run, latency/run, failure/repair/fallback rates.
- Plain statement of whether debate helped. If it did not, say so — do not hide it.
- Limitations paragraph (judge bias, sample size, model versions).

## Step 5 — Grounding (P0)
- Market agent: add web-search tool; every market figure must carry `source_url` + `retrieved_at`, else labeled `"assumption"` in the schema.
- Cost estimates: load a pinned pricing file (`data/cloud_pricing.json`, with source and date) instead of free-form LLM guesses. If pricing can't be fetched, mark `"estimate_unverified"`.
- Add a fact-check node: scans final deliverables, flags claims lacking a source/assumption label, and appends a "Verification" appendix. Update schemas + tests + exports to include source columns.

## Step 6 — Reliability
Add tests (mocked LLM) for: malformed JSON → repair, provider outage → fallback, debate loop cap, prompt injection in the idea text, budget cap exceeded → graceful stop with partial output. Report rates in ABLATION.md.

## Step 7 — Human-in-the-loop (P1)
Use LangGraph `interrupt` before the pitch-deck stage so the user can approve/edit the PRD. Add UI control + test.

## Step 8 — Observability
Integrate Langfuse or LangSmith (env-var enabled, off by default). Document setup; leave a `<TODO owner: add trace screenshot>` placeholder in README.

## Step 9 — CI + packaging
- GitHub Actions: lint, tests (mocked LLM), schema tests, Docker build. Add badge + coverage.
- `docker compose up` from clean clone; `.env.example` with provider setup (incl. bring-your-own-key mode and rate limiting for public demo).
- Commit 3 sample outputs to `examples/` (generated by real runs; label model + date).

## Step 10 — Docs
README order: pitch + walkthrough placeholders → ablation table → LangGraph diagram (Mermaid) → grounding explanation → reliability numbers → quick start → eval reproduction → limitations. Add `docs/DECISIONS.md` (mark inferred rationale "inferred — owner to confirm").

## Step 11 — Technical summary bullet (output only, do not commit)
Using only numbers from `eval/results/`:
> Built LangGraph multi-agent venture engine (FastAPI, React) producing market sizing, PRD, architecture, cost estimates and pitch deck; ablation on N ideas showed debate changed rubric score A → B (human-validated on M) at +C% cost; source-cited market figures; schema repair/fallback keep failure rate at D%.
